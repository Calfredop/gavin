Add Kimi Code CLI (`kimi`) as Gavin's sixth stock agent profile with full parity to claude-code. Designed in a grilling session (2026-10-05); facts verified against kimi 2.1.1 on this machine plus the official docs (moonshotai.github.io/kimi-code, www.kimi.com/code/docs/en/).

## Decided (2026-10-05)

- **K1 — Full parity (claude-code), one card.** Every profile column Kimi's surface can support; what it cannot is a documented absence, never a stub. Repo rule stands: no row on an unverified convention — the spike lands first, like opencode.
- **K2 — Stock profile, not custom.** Custom profiles cannot get: instructions-block/skill installation, usage probe, token log, headroom recipe, failure patterns, wizard detection.
- **K3 — Visible runs get their prompt by injection, not argv.** Kimi has NO interactive prompt flag (verified `kimi --help` + docs): `-p` is non-interactive and exits; there is no positional. Mechanism (the human's design): spawn `kimi` bare; when kimi connects to the gavin MCP server at session start, that `initialize` handshake IS the "agent ready" callback (gavin-mcp already knows its `GAVIN_SESSION_ID`/`GAVIN_SESSION_SOCKET`); the daemon then writes the composed card prompt + Enter into the PTY — the same write path as human keystrokes. Spike must confirm: MCP connects eagerly at TUI start, and the TUI is input-ready by handshake time. Fallback ready-signal: the daemon's existing OSC-133/quiet heuristics. If injection proves unworkable, escalate to the human before falling back to `prompt_args: None` (which would mean no visible card runs — `buildRunCommand` returns null).
- **K4 — Headless runs: `kimi -p '<prompt>'`.** Runs under the `auto` permission policy by default (no approvals; static deny rules apply). Flag conflicts: `-p` cannot combine with `--yolo`/`--auto`/`--plan`. `--output-format stream-json` available if wanted.
- **K5 — Model via `-m <alias>`; effort via env prefix, not a flag.** No effort CLI flag exists (docs-verified); the TUI picker is config-backed. `KIMI_MODEL_THINKING_EFFORT=<low|medium|high|xhigh|max>` is a documented runtime switch (kimi provider only, bypasses `support_efforts`); Gavin composes launch commands through `sh -c`, so an env prefix composes like a flag. Live-spike-verified before the column ships; if it fights, effort ships absent (documented gap).
- **K6 — MCP layout: project `.mcp.json`, `JsonServers` dialect — same as claude-code.** Proven live: this repo's root `.mcp.json` is what loaded gavin's tools into a kimi session. No new `McpFormat` variant. Kimi also reads `~/.kimi-code/mcp.json` and `<cwd>/.kimi-code/mcp.json`; gavin writes only the project `.mcp.json` under the `gavin` key, with the existing foreign-server disclosure gate.
- **K7 — Instructions file: `AGENTS.md`** (kimi reads AGENTS.md/agents.md only — NOT CLAUDE.md/KIMI.md). Shared with codex; the marker-block writer already merges.
- **K8 — Skills install to `.kimi-code/skills/<name>/SKILL.md`.** Kimi also reads the shared `.agents/skills/`, but gavin keeps its files in kimi's own root — same reasoning as opencode's O5.
- **K9 — Resume is discover-not-mint (opencode pattern).** Gavin cannot mint session ids (verified: `--session <unknown>` hard-errors). Discovery: kimi prints `To resume this session: kimi -r session_<uuid>` on stderr after `-p` runs; also `kimi session list --json [--cwd]` and `~/.kimi-code/session_index.jsonl`. `resume_args`: `--session`. `--continue` is newest-for-cwd — same race opencode's V11e demonstrated; do not use it for card resume.
- **K10 — Failure patterns from verified strings.** `error: failed to run prompt: <reason>` (stderr, verified), plus i18n strings: "Model rate limit reached", "Model authentication failed", "Model overloaded", "Context size exceeded", "Cannot connect to the model service". Status detection is free: kimi emits OSC 133 zones and OSC 9 notifications, which the daemon's StatusScanner already reads.
- **K11 — Usage probe: spike, then implement-or-absent.** Third-party trackers (kimi-code-usage) read quota from `api.kimi.com/coding` with a CONSOLE API key (`sk-kimi-xxx`). Spike question: do the stored membership OAuth credentials (`~/.kimi-code/credentials/kimi-code-env-*.json`, AnthropicOauth-probe pattern) authorize an equivalent usage call? If yes: `UsageProbe::KimiOauth`. If no: absent — gavin will not ask users to mint console keys, and will NOT spawn `kimi web` to reach its localhost `/api/v1/oauth/usage`.
- **K12 — Token log: `KimiWireJsonl`.** Per-session `~/.kimi-code/sessions/<wd_key>/<session_id>/agents/<agent_id>/wire.jsonl` carries `usage.record` and `token_counting.*` events; `wd_key = wd_<slug>_<sha256(cwd)[:12]>`; global index `~/.kimi-code/session_index.jsonl` maps sessionId→dir.
- **K13 — Headroom: research-first gate, non-blocking.** Kimi's managed provider is OpenAI-compatible traffic to `api.kimi.ai/coding/v1` (NOT Anthropic). Candidate route: `KIMI_CODE_BASE_URL` env (documented; managed OAuth service only) → Headroom's OpenAI-compatible endpoint (codex family). Clean reuse → implement `Agent::Kimi` in `compress.rs` (`from_profile`, `from_command`, `is_stock_profile_id`, `recipe`, `inherited_routing`). Bespoke → `UnsupportedAgent` like cursor, recorded, does not block the card.
- **K14 — No superpowers row.** Superseded by the live card `feat-replace-superpower.md`; the kimi work must not add a `superpowers.rs` mechanism.
- **K15 — ACP/REST out of scope.** `kimi acp` and `kimi web` (REST+WS, structured session-status events) are a richer steering surface but a different architecture than gavin's PTY+scanner model; recorded here as a future direction only.
- **K16 — macOS-verified is sufficient** (as all five stock agents landed); cross-platform risk rides the existing cross-platform verification cards.
- **K17 — No protocol bump.** Profile data rides Tauri commands (opencode O7 precedent).

## Spike findings (2026-10-05, kimi 2.1.1 live on this machine)

- **argv (K4)**: `-p/--prompt`, `-m/--model`, `-S/--session [id]`, `-c/--continue`, `--output-format text|stream-json`, `--yolo/--auto/--plan`, `--agent`, `--skills-dir` confirmed via `--help`. `-p` conflicts: `error: Cannot combine --prompt with --auto|--yolo|--plan` (exact strings). `-r` is a working resume alias (not in help, used by kimi's own stderr hint).
- **Resume (K9)**: stderr after every `-p` run prints `To resume this session: kimi -r session_<uuid>` — confirmed. `kimi --session <unknown>` and `-r <unknown>` hard-error: `Session "..." not found.` Resume carries context (re-resumed session recalled earlier content). `kimi session list --json` lists cwd sessions (id, workDir, sessionDir, timestamps; `--cwd` takes a required path arg, contrary to the card's `[--cwd]`). `~/.kimi-code/session_index.jsonl` maps sessionId→sessionDir+workDir (workDir is the PHYSICAL path, `/private/tmp/...` — same `pwd -P` caveat as opencode).
- **Token log (K12)**: `~/.kimi-code/sessions/<wd_key>/<session_id>/agents/<agent_id>/wire.jsonl` confirmed; `wd_key = wd_<slug>_<sha256(cwd)[:12]>` reproduced exactly. `usage.record` = `{usage: {inputOther, output, inputCacheRead, inputCacheCreation}, usageScope: "turn"}`; `token_counting.turn_recorded`/`measured` carry context-length tokens. Note: `transcript_path(root, conversation_id)` has no cwd — resolve via `session_index.jsonl`, not path derivation.
- **Effort (K5) — corrected**: `KIMI_MODEL_THINKING_EFFORT=low` DID apply — verified at the wire through a local proxy: request body carried `thinking: {type: "enabled", effort: "low"}`. Caveat: wire.jsonl's `profile.bind`/`llm.request` still record the CONFIGURED default (high); the env override applies at request build. So the env composes as a launch prefix; gavin's effort mechanism needs an env-prefix shape, not a flag.
- **Usage probe (K11) — GO**: `~/.kimi-code/credentials/kimi-code-env-<hash>.json` holds `{access_token, refresh_token, expires_at, ...}`. `GET <base>/usages` with `Authorization: Bearer <access_token>` returned HTTP 200 on BOTH `api.kimi.ai/coding/v1` and `api.kimi.com/coding/v1`. Wire shape is snake_case: `{limits: [{window, detail:{limit, remaining, resetTime}}], usages: {limit_5h: {used_ratio, reset_time}, limit_month_total, limit_month_code}}`. kimi's own client posts to `<base>/usages` (managed-usage.ts) — same endpoint.
- **Headroom (K13) — route works, one caveat**: `KIMI_CODE_BASE_URL=http://127.0.0.1:8798/v1` redirected real chat traffic through a local forward proxy end-to-end (PROXY_OK). kimi appends `/chat/completions` to the base (base keeps its `/v1`). CAVEAT: with the env set, the OAuth credential slot is re-derived as `oauth/kimi-code-env-<sha256({oauthHost, baseUrl})[:16]>` with oauthHost = `KIMI_CODE_OAUTH_HOST ?? https://auth.kimi.com`; a global-region user (persisted host `auth.kimi.ai`) needs `KIMI_CODE_OAUTH_HOST` exported too, and the derived slot must contain a credential file (formula verified byte-exact against the existing slot `env-0e4f99c69cc27850`; copying the file works). Implement with the slot copy, or ship `UnsupportedAgent` — human call if contested.
- **Prompt injection (K3) — works**: project `.mcp.json` server was spawned EAGERLY at TUI startup (initialize + notifications/initialized + tools/list within ~5ms); a prompt written into the PTY as keystrokes after startup was accepted and answered. OSC 133 zones (9) and OSC 9 notifications (21) emitted during a turn — the daemon's StatusScanner reads kimi natively, and the quiet-timer/OSC-133 fallback ready signal exists.
- **Trust gate (NEW, K18)**: untrusted folder → interactive TUI stops at a "Trust this folder?" screen listing project MCP servers; headless `-p` SKIPS project MCP servers with `Warning: this folder is not trusted; skipped 1 project-level MCP server: ...`. Trust store: `~/.kimi-code/workspace-trust/wd_<key>` = `{"root": <physical path>, "trustedAt": <ms>}`. Integration should detect/offer trust for the workspace, or document that the first kimi run asks.
- **Trust gate verified and built (2026-10-06, kimi 2.1.1, scratch `KIMI_CODE_HOME`, read out of the binary)**: (a) untrusted → `Warning: this folder is not trusted; skipped 1 project-level MCP server`; (b) after a record written with the algorithm below the warning is gone and the run reaches the model step; (c) trusting a PARENT leaves a child directory's warning standing — a worktree is its own workspace. Key = kimi's `encodeWorkDirKey(canonicalWorkspaceRoot(cwd))`: backslashes → `/`, trailing `/` dropped, a drive/UNC-shaped path lowercased; `wd_<slug>_<sha256(path)[:12]>` with slug = last segment lowercased, runs outside `[a-z0-9._-]` → `-`, trimmed, cut to 40, trimmed, `workspace` if empty. Reproduced byte-for-byte against the keys kimi itself wrote. kimi keys on its own cwd, the PHYSICAL path, so gavin canonicalises the root first. The gate covers PROJECT MCP servers only (`includeProject: trust.isTrusted()`): `<git work tree root>/.mcp.json` and `<cwd>/.kimi-code/mcp.json`; the user-level `~/.kimi-code/mcp.json` is ungated. Declining at the interactive prompt exits kimi.
- **Model catalog (NEW)**: `kimi provider list --json` emits providers + full model map (aliases, supportEfforts, defaultEffort, displayName) — a `ModelCatalog` route analogous to OpencodeCli. Aliases are managed/upstream-refreshed, so `models: &[]` stays.
- **Isolation knob (NEW)**: `KIMI_CODE_HOME` relocates the whole kimi home — use it in tests/live-pass scratch setups.
- **Failure strings (K10)**: `error: failed to run prompt: <reason>` observed live 4×. i18n quota strings remain docs-sourced.
